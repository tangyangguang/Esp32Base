# Web UI 页面结构与样式基线

## 1. 定位

本文档定义 Esp32Base Web 页面结构、样式基线和业务页面复用方式。

它服务两类页面：

- 基础库内置页面，例如 Status、WiFi、Logs、System、Auth、OTA、App Config。
- 业务自定义页面，例如设备首页、业务配置、记录列表、操作命令、校准流程、诊断维护。

这套基线不是大型前端框架，也不是业务页面集合。它只提供轻量、紧凑、统一、可裁剪的页面表达能力，让业务项目不用反复调 CSS 和基础布局。

## 2. 设计目标

目标：

- PC 和手机浏览器都能保持良好可读性和可操作性。
- 页面简洁、大方、信息表达清楚。
- 配色克制，默认适合设备管理界面。
- 页面资源小，适合 ESP32 同步 WebServer 输出。
- 样式变化集中在基础 CSS 和 helper 结构里，不散落到业务项目。
- 业务项目可以按需使用统一模板，不被具体业务项目绑定。

非目标：

- 不做 SPA。
- 不做 WebSocket 依赖。
- 不引入前端框架。
- 不引入图表库。
- 不做运行时主题编辑器。
- 不做图片皮肤或重视觉资产。
- 不让基础库接管业务数据模型。

## 3. 分类原则

模板按页面能力分类，不按业务功能分类。

正确分类方式：

- 状态概览。
- 访问控制。
- 统计摘要。
- 列表记录。
- 配置编辑。
- 操作命令。
- 确认保护。
- 横向状态。
- 流程向导。
- 诊断维护。

不按以下方式分类：

- 灌溉总览。
- 风扇配置。
- 接水记录。
- 饲料桶设置。
- 某个业务项目的某个功能页。

业务页面应由能力模板组合出来，而不是让基础库提供业务组件。

## 4. 基础壳层

所有页面共享同一基础壳层：

1. 设备身份栏或紧凑导航上下文。
2. 横向导航。
3. 页面标题区。
4. 页面内容区。
5. 页脚状态或系统入口。

规则：

- 顶部不放无意义装饰图标。
- 设备在线、异常、受限等状态优先用有效信息表达。
- PC 内容最大宽度控制在约 1180px，避免宽屏拉散。
- 手机端允许导航横向滚动或内容自然堆叠。
- 标题、导航、section、表单控件使用统一密度。
- 卡片和 panel 只用于分组，不做多层嵌套卡片。

## 5. 首版页面能力

### 5.1 访问控制

用途：

- 登录。
- 权限不足。
- 会话失效。
- 只读受限。

规则：

- 登录页使用统一表单样式。
- 权限不足必须说明原因和可继续做什么。
- 不用浏览器弹窗代替页面级反馈。
- 提交仍使用 `POST -> 303 -> GET`。

### 5.2 状态概览

用途：

- 设备首页。
- 任何需要快速判断当前状态的页面。

结构：

- 当前状态。
- 关键指标。
- 下一计划或最近记录。
- 主操作入口。
- 异常摘要。

规则：

- 首行回答设备是否正常。
- 关键指标不超过 4 个。
- 异常优先于普通摘要。
- 首页只保留有限主操作，不做大仪表盘。

### 5.3 统计摘要

用途：

- 累计值。
- 分组汇总。
- 轻量趋势。
- 成功率、用量、次数、占比等摘要。

规则：

- 用数字、表格、CSS 条形或极简内联元素表达。
- 不引入图表库。
- 不在摘要页堆满明细，明细进入记录页。
- 它补齐状态概览和记录列表之间的空档。

### 5.4 列表记录

用途：

- 历史记录。
- 事件列表。
- 对象列表。

结构：

- 紧凑筛选区。
- 表头。
- 数据行。
- 分页 footer。
- 空状态。

分页规则：

- 显示总条数、当前页和总页数。
- 提供首页、上一页、下一页、尾页。
- 总页数可知时允许跳页。
- 筛选变化后回到第一页。
- 手机端保留核心分页动作，不展示过密页码。

筛选规则：

- 筛选区不平均拉满宽度。
- 时间范围支持最近 24 小时、最近 7 天、最近 30 天和自定义。
- 自定义时间使用开始时间和结束时间。
- 翻页保留筛选条件。

### 5.5 配置编辑

用途：

- 业务配置。
- 通道配置。
- 计划配置。
- 低频参数。

规则：

- 默认先展示当前值，不直接铺开大表单。
- 简单字段可行内展开编辑。
- 多字段对象进入独立编辑页。
- 每项必须有一句必要说明。
- 高风险配置进入确认保护页。
- 系统级基础参数优先使用 App Config。
- 业务运行状态不放进配置表单。

### 5.6 操作命令

用途：

- 开始。
- 停止。
- 跳过。
- 测试。
- 立即执行。

规则：

- 命令不是配置，不保存为长期参数。
- 执行前必须判断可执行条件。
- 执行中不显示新的开始按钮。
- 停止按钮必须容易找到。
- 拒绝执行必须说明原因和下一步。
- 高风险命令进入确认保护页。

### 5.7 确认保护

用途：

- 恢复出厂。
- 重置计数。
- 清除故障。
- 保存高风险校准。
- 格式化文件系统。
- 重启或维护操作。

规则：

- 高风险动作进入独立确认页。
- 不只依赖浏览器 `confirm()`。
- 确认页展示对象、当前状态、影响范围和返回位置。
- 服务端 POST 时重新校验状态和权限。
- 必要时使用一次性 token。
- 成功、失败或拒绝应能追溯到日志或业务记录。

### 5.8 横向状态

用途：

- 保存成功。
- 保存失败。
- 无数据。
- 未配置。
- 运行中拒绝。
- 权限不足。
- 时间未同步。
- 存储或网络不可用。

规则：

- 保存成功或失败用顶部短提示。
- 页面主体没有内容时才使用大空状态。
- 空状态说明原因和下一步。
- 错误不能只显示“失败”。
- 时间未同步要说明受影响功能和仍可使用功能。

### 5.9 流程向导

用途：

- 校准。
- 首次设置。
- 复杂维护。

规则：

- 按“依据、实测、核对、保存”组织。
- 不把校准塞进普通配置表单。
- 保存前展示旧值、新值、变化幅度和影响范围。
- 状态不可信时禁止保存关键校准。
- 保存仍使用 `POST -> 303 -> GET`。

### 5.10 诊断维护

用途：

- 系统信息。
- 只读诊断。
- 维护入口。
- 长任务状态。
- 受控原始片段。

规则：

- 默认只读优先。
- 危险维护动作进入确认保护页。
- 长任务不单独成为页面类型，只作为操作或维护状态变体。
- 原始数据不单独成为模板，只作为受控片段。
- 原始片段限制长度，可复制或导出。
- 不做无限滚动调试平台。

## 6. 样式基线

默认视觉：

- 中性灰背景。
- 白色内容面。
- 低饱和主色。
- 明确语义色。
- 6-8px 圆角。
- 32-34px 控件高度。
- 10-12px section 内边距。
- 正文 14px。
- 页面标题 22-24px。
- section 标题 16-17px。

配色语义：

- 主色用于导航、主按钮和少量强调。
- 成功、警告、危险、信息色只用于语义反馈。
- 不把危险色、警告色当装饰色。
- 不使用大面积渐变、装饰光斑或图片背景。

## 7. 皮肤策略

首版支持 CSS 变量级皮肤。

业务项目可覆盖：

- 主色。
- 主色浅背景。
- 页面背景。
- 内容面。
- 边框色。
- 语义色。

业务项目不应覆盖：

- 成功、警告、危险、信息的语义含义。
- 基础布局层级。
- 表单和按钮的可操作性。

推荐方式：

```cpp
void handleHeadExtra() {
    Esp32BaseWeb::sendChunk(
        "<style>:root{--eb-primary:#245f9e;--eb-primary-soft:#e8f0f8}</style>"
    );
}
```

不做：

- 运行时主题编辑器。
- 图片皮肤。
- 大型 CSS 框架。
- 业务项目复制整套 CSS。

## 8. 与现有 Web 代码的关系

现有入口继续保留：

- `Esp32BaseWeb::addPage()`。
- `Esp32BaseWeb::addRoute()`。
- `Esp32BaseWeb::addNavItem()`。
- `Esp32BaseWeb::sendHeader()`。
- `Esp32BaseWeb::sendFooter()`。
- `Esp32BaseWeb::sendChunk()`。
- `Esp32BaseWeb::setHeadExtraCallback()`。
- `Esp32BaseWeb::redirectSeeOther()`.

新增能力应以 helper 形式提供，例如：

- `sendPageTitle()`：页面标题。
- `beginPanel()` / `endPanel()`：内容分组。
- `sendNotice()` / `sendResultNotice()`：页面级反馈。
- `beginMetricGrid()` / `sendMetric()` / `endMetricGrid()`：状态和统计摘要。
- `sendInfoRowCompact()`：只读紧凑行。
- `sendInfoRowCompactLink()`：带安全链接动作的紧凑行。
- `sendInfoRowCompactForm()`：带单按钮 POST 动作的紧凑行。
- `sendPagination()`：页码型分页。

行内动作优先使用 `sendInfoRowCompactLink()` 或 `sendInfoRowCompactForm()`。如果业务确实需要自定义 HTML，使用底层 `sendChunk()` 手动输出；来自配置、URL、日志、设备名、用户输入或远端数据的内容不得直接拼接，必须使用 `writeHtmlEscaped()`。

业务项目仍负责：

- 具体业务数据。
- 字段定义。
- 操作含义。
- 权限和状态判断。
- 参数校验。

基础库负责：

- 页面结构。
- 默认样式。
- 常见 UI 语义。
- 分页展示。
- PRG 提交路径。
- 可换肤变量。

## 9. 提交与防重复规则

所有表单和命令提交默认遵守：

```text
POST -> 303 Redirect -> GET
```

规则：

- 成功和失败都跳回 GET 页面。
- 刷新不能重复提交。
- 前端禁用按钮只防连点，不替代服务端校验。
- 服务端必须重新解析参数、校验范围、检查设备状态和权限。
- GET 页面通过 query 或结果状态显示短提示。

## 10. 示例与验证

首版示例应覆盖：

- 设备首页。
- 访问控制页。
- 统计摘要页。
- 记录列表页。
- 配置编辑页。
- 操作命令页。
- 流程向导页。
- 诊断维护页。

示例位置：

- `examples/full_demo`

验证重点：

- PC 宽屏不拉散。
- 手机端不重叠。
- 表单控件对齐。
- 分页信息完整。
- 成功和失败状态可见。
- 刷新不重复提交。
- 皮肤变量覆盖后仍保持语义清楚。

## 11. 样式调整回路

实现和试用过程中允许调整样式。

调整原则：

- 优先改基础 CSS 变量或通用 class。
- 其次改 helper 输出结构。
- 不在业务页面堆一次性 CSS。
- 不为了单个项目加入业务组件。
- 每次样式调整先更新 `examples/full_demo`，再扩散到业务项目。

影响判断：

- 颜色、间距、字号、圆角属于小改。
- 配置行、分页 footer、导航结构属于中改。
- 页面能力分类或 helper API 变化属于大改。

大改必须先回到设计文档和示例页验证。
