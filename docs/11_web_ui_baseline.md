# Web UI 页面结构与样式基线

## 1. 定位

本文档定义 Esp32Base Web 页面结构、样式基线和业务页面复用方式。

它服务两类页面：

- 基础库内置页面，例如 Status、WiFi、Logs、System、Auth、OTA、App Config。
- 业务自定义页面，例如设备首页、业务配置、记录列表、操作命令、校准流程、诊断维护。

这套基线不是大型前端框架，也不是业务页面集合。它只提供轻量、紧凑、统一、可裁剪的页面表达能力，让业务项目不用反复调 CSS 和基础布局。

## 2. 设计目标

目标：

- PC 和手机浏览器都能保持良好可读性和可操作性。
- 页面简洁、大方、信息表达清楚。
- 配色克制，默认适合设备管理界面。
- 页面资源小，适合 ESP32 同步 WebServer 输出。
- 样式变化集中在基础 CSS 和 helper 结构里，不散落到业务项目。
- 业务项目可以按需使用统一模板，不被具体业务项目绑定。

非目标：

- 不做 SPA。
- 不做 WebSocket 依赖。
- 不引入前端框架。
- 不引入图表库。
- 不做运行时主题编辑器。
- 不做图片皮肤或重视觉资产。
- 不让基础库接管业务数据模型。

## 3. 分类原则

模板按页面能力分类，不按业务功能分类。

正确分类方式：

- 状态概览。
- 访问控制。
- 统计摘要。
- 列表记录。
- 配置编辑。
- 操作命令。
- 确认保护。
- 横向状态。
- 流程向导。
- 诊断维护。

不按以下方式分类：

- 灌溉总览。
- 风扇配置。
- 接水记录。
- 饲料桶设置。
- 某个业务项目的某个功能页。

业务页面应由能力模板组合出来，而不是让基础库提供业务组件。

## 4. 业务项目接入规则

业务项目接入 Web UI baseline 时，先按页面能力选择基础库提供的结构、helper 和 CSS 类，不在业务项目里临时复制基础库 CSS、手写一套局部布局，或用一次性样式绕开基础库。

判断规则：

- 现有能力块能表达页面结构时，业务页面只填充业务数据和必要动作。
- 找不到合适能力块时，先视为 Esp32Base 的能力、命名或文档需要评估。
- 多个 ESP32 项目可能复用的页面模式，应回到 Esp32Base 补统一能力块、CSS/helper、示例和文档。
- 只有确认场景是业务独有且不会复用时，才允许业务侧做最小局部实现；局部实现仍应复用基础壳层、字号、按钮、表单、提示和分页样式。

给基础库会话的提示词模板：

```text
我在业务项目接入 Esp32Base Web UI baseline 时，遇到一个页面场景找不到合适的能力块。

业务场景：
- 页面用途：
- 需要展示、编辑或操作的数据：
- 当前尝试使用的 Esp32Base 能力块：
- 为什么不合适：
- 是否可能在多个 ESP32 项目复用：
- 期望效果或截图：

请先评估这是否应该沉淀为 Esp32Base 的通用 Web UI 能力。
如果应该，请补充统一的页面能力块、CSS/helper、示例和文档；
如果不应该，请说明业务侧应该如何最小化实现，避免破坏整体 UI baseline。
```

## 5. 基础壳层

所有页面共享同一基础壳层：

1. 设备身份栏或紧凑导航上下文。
2. 横向导航。
3. 页面标题区。
4. 页面内容区。
5. 页脚状态或系统入口。

规则：

- 顶部不放无意义装饰图标。
- 设备在线、异常、受限等状态优先用有效信息表达。
- PC 内容最大宽度控制在约 1180px，避免宽屏拉散。
- 手机端允许导航横向滚动或内容自然堆叠。
- 标题、导航、section、表单控件使用统一密度。
- 字号层级应服务主次关系：顶部主导航和正文为 14px，页面标题约 18px，section 标题约 16px，底部低频系统入口 12px 且高度收敛，运行摘要 11px。
- 卡片和 panel 只用于分组，不做多层嵌套卡片。
- 顶部导航只放高频主入口；子页面使用父级路径前缀，让父级导航保持高亮。

## 6. 首版页面能力

### 6.1 访问控制

用途：

- 登录。
- 权限不足。
- 会话失效。
- 只读受限。

规则：

- 登录页使用统一表单样式。
- 权限不足必须说明原因和可继续做什么。
- 不用浏览器弹窗代替页面级反馈。
- 提交仍使用 `POST -> 303 -> GET`。

### 6.2 状态概览

用途：

- 设备首页。
- 任何需要快速判断当前状态的页面。

结构：

- 当前状态。
- 关键指标。
- 下一计划或最近记录。
- 主操作入口。
- 异常摘要。

规则：

- 首行回答设备是否正常。
- 关键指标不超过 4 个。
- 基础库 Status 页采用“Device Health 摘要 + 紧凑诊断分区 + 末尾详细表”的结构；业务设备首页也应优先让用户先判断状态，再进入详细信息。
- 异常优先于普通摘要。
- 首页只保留有限主操作，不做大仪表盘。

### 6.3 统计摘要

用途：

- 累计值。
- 分组汇总。
- 轻量趋势。
- 成功率、用量、次数、占比等摘要。

规则：

- 用数字、表格、CSS 条形或极简内联元素表达。
- 不引入图表库。
- 不在摘要页堆满明细，明细进入记录页。
- 它补齐状态概览和记录列表之间的空档。

### 6.4 列表记录

用途：

- 历史记录。
- 事件列表。
- 对象列表。

结构：

- 紧凑筛选区。
- 表头。
- 数据行。
- 分页 footer。
- 空状态。

分页规则：

- 显示总条数、当前页和总页数。
- 提供首页、上一页、下一页、尾页。
- 提供当前页附近的页码，默认不铺满全部页码。
- 提供每页条数选择和跳页提交。
- 总页数可知时允许跳页。
- 筛选变化后回到第一页。
- 手机端保留核心分页动作，不展示过密页码。
- 分页区的字号、按钮高度、字重和颜色应比主操作更轻；当前页可有轻量强调，但不使用主按钮重色。
- 当前页由页码本身表达，不在每页条数和跳页区域重复输出“当前第 N 页”。

筛选规则：

- 筛选区不平均拉满宽度。
- 时间范围支持最近 24 小时、最近 7 天、最近 30 天和自定义。
- 预设时间范围不展示开始时间和结束时间；自定义时间才展示开始时间和结束时间。
- 翻页保留筛选条件。
- 筛选区应使用真实表单控件，不用静态标签冒充筛选。
- 筛选控件已经展示当前条件时，不再额外输出重复的筛选摘要标签。

### 6.5 配置编辑

用途：

- 业务配置。
- 通道配置。
- 计划配置。
- 低频参数。

规则：

- 默认先展示当前值，不直接铺开大表单。
- 简单字段可行内展开编辑。
- 多字段对象进入独立编辑页。
- 每项必须有一句必要说明。
- 行动作必须使用按钮型链接或按钮，不使用状态标签尺寸承载点击动作。
- 同一行同时有状态值和动作时，状态值与动作按钮必须有明确间距，不把状态挤在按钮旁边。
- 同组紧凑行右侧必须形成稳定的值列和动作列，避免不同按钮宽度造成状态值竖向不齐。
- 同组内只读状态值应和带动作行的状态值位置保持一致，不贴到动作按钮列最右侧。
- 高风险配置进入确认保护页。
- 系统级基础参数优先使用 App Config。
- 低频但不适合放入 App Config 的内置配置，使用 `formpanel`、`editform`、`fieldgrid` 和 `field` 结构；字段宽度按短字段、普通字段、长文本字段区分，不把所有输入框拉满整行。
- 只读系统参数和少量可修改字段在同一块中出现时，先用 `kv` 表格展示当前值，再在同一 panel 下方放编辑表单。
- 业务运行状态不放进配置表单。

### 6.6 操作命令

用途：

- 开始。
- 停止。
- 跳过。
- 测试。
- 立即执行。

规则：

- 命令不是配置，不保存为长期参数。
- 执行前必须判断可执行条件。
- 执行中不显示新的开始按钮。
- 停止按钮必须容易找到。
- 拒绝执行必须说明原因和下一步。
- 普通低频操作使用 `actionpanel`；只读元信息用 `tablewrap + kv`，操作选项用真实 radio/select/form 控件，不用静态链接冒充表单状态。
- 高风险命令进入确认保护页。

### 6.7 确认保护

用途：

- 恢复出厂。
- 重置计数。
- 清除故障。
- 保存高风险校准。
- 格式化文件系统。
- 重启或维护操作。

规则：

- 高风险动作进入独立确认页。
- 内置 System 页内的重启、格式化、清日志、清 WiFi 等低频维护动作使用 `dangerpanel`，在视觉上与普通设置区分，但不使用大面积警告色。
- 危险操作仍必须使用 POST、`confirm()`、`once(form)` 和 `POST -> 303 -> GET`，避免刷新重复提交。
- 不只依赖浏览器 `confirm()`。
- 确认页展示对象、当前状态、影响范围和返回位置。
- 服务端 POST 时重新校验状态和权限。
- 必要时使用一次性 token。
- 成功、失败或拒绝应能追溯到日志或业务记录。

### 6.8 横向状态

用途：

- 保存成功。
- 保存失败。
- 无数据。
- 未配置。
- 运行中拒绝。
- 权限不足。
- 时间未同步。
- 存储或网络不可用。

规则：

- 保存成功或失败用顶部短提示。
- 页面主体没有内容时才使用大空状态。
- 空状态说明原因和下一步。
- 错误不能只显示“失败”。
- 时间未同步要说明受影响功能和仍可使用功能。

### 6.9 流程向导

用途：

- 校准。
- 首次设置。
- 复杂维护。

规则：

- 按“依据、实测、核对、保存”组织。
- 不把校准塞进普通配置表单。
- 保存前展示旧值、新值、变化幅度和影响范围。
- 状态不可信时禁止保存关键校准。
- 保存仍使用 `POST -> 303 -> GET`。

### 6.10 诊断维护

用途：

- 系统信息。
- 只读诊断。
- 维护入口。
- 长任务状态。
- 受控原始片段。

规则：

- 默认只读优先。
- 危险维护动作进入确认保护页。
- 长任务不单独成为页面类型，只作为操作或维护状态变体。
- 原始数据不单独成为模板，只作为受控片段。
- 原始片段限制长度，可复制或导出。
- 不做无限滚动调试平台。

## 7. 样式基线

默认视觉：

- 中性灰背景。
- 白色内容面。
- 低饱和主色。
- 明确语义色。
- 6-8px 圆角。
- 32-34px 控件高度。
- 10-12px section 内边距。
- 正文 14px。
- 页面标题 22-24px。
- section 标题 16-17px。

配色语义：

- 主色用于导航、主按钮和少量强调。
- 成功、警告、危险、信息色只用于语义反馈。
- 不把危险色、警告色当装饰色。
- 不使用大面积渐变、装饰光斑或图片背景。

## 8. 皮肤策略

首版支持 CSS 变量级皮肤。

业务项目可覆盖：

- 主色。
- 主色浅背景。
- 页面背景。
- 内容面。
- 边框色。
- 语义色。

业务项目不应覆盖：

- 成功、警告、危险、信息的语义含义。
- 基础布局层级。
- 表单和按钮的可操作性。

推荐方式：

```cpp
void handleHeadExtra() {
    Esp32BaseWeb::sendChunk(
        "<style>:root{--eb-primary:#245f9e;--eb-primary-soft:#e8f0f8}</style>"
    );
}
```

不做：

- 运行时主题编辑器。
- 图片皮肤。
- 大型 CSS 框架。
- 业务项目复制整套 CSS。

## 9. 与现有 Web 代码的关系

现有入口继续保留：

- `Esp32BaseWeb::addPage()`。
- `Esp32BaseWeb::addRoute()`。
- `Esp32BaseWeb::addNavItem()`。
- `Esp32BaseWeb::sendHeader()`。
- `Esp32BaseWeb::sendFooter()`。
- `Esp32BaseWeb::sendChunk()`。
- `Esp32BaseWeb::setHeadExtraCallback()`。
- `Esp32BaseWeb::redirectSeeOther()`.

新增能力应以 helper 形式提供，例如：

- `sendPageTitle()`：页面标题。
- `beginPanel()` / `endPanel()`：内容分组。
- `sendNotice()` / `sendResultNotice()`：页面级反馈。
- `beginMetricGrid()` / `sendMetric()` / `endMetricGrid()`：状态和统计摘要。
- `sendInfoRowCompact()`：只读紧凑行。
- `sendInfoRowCompactLink()`：带按钮型链接动作的紧凑行。
- `sendInfoRowCompactForm()`：带单按钮 POST 动作的紧凑行。
- `sendPagination()`：页码型分页，包含每页条数和跳页提交。

行内动作优先使用 `sendInfoRowCompactLink()` 或 `sendInfoRowCompactForm()`。如果业务确实需要自定义 HTML，使用底层 `sendChunk()` 手动输出；来自配置、URL、日志、设备名、用户输入或远端数据的内容不得直接拼接，必须使用 `writeHtmlEscaped()`。

业务项目仍负责：

- 具体业务数据。
- 字段定义。
- 操作含义。
- 权限和状态判断。
- 参数校验。

基础库负责：

- 页面结构。
- 默认样式。
- 常见 UI 语义。
- 分页展示。
- PRG 提交路径。
- 可换肤变量。

基础样式由 `/esp32base/ui.css` 输出，页面通过 `sendHeader()` 自动引用。业务页面不需要手动引用该 CSS，也不应该复制整段基础 CSS；浏览器会缓存该资源，避免每个页面重复下载同一份样式。

## 10. 提交与防重复规则

所有表单和命令提交默认遵守：

```text
POST -> 303 Redirect -> GET
```

规则：

- 成功和失败都跳回 GET 页面。
- 刷新不能重复提交。
- 前端禁用按钮只防连点，不替代服务端校验。
- 服务端必须重新解析参数、校验范围、检查设备状态和权限。
- GET 页面通过 query 或结果状态显示短提示。

## 11. 示例与验证

首版示例应覆盖：

- 设备首页。
- 访问控制页。
- 统计摘要页。
- 记录列表页。
- 配置编辑页。
- 操作命令页。
- 流程向导页。
- 诊断维护页。

示例位置：

- `examples/web_ui_gallery`：专门用于查看和验收 Web UI baseline 的页面能力与样式，覆盖状态、统计、分页记录、配置、命令、流程、维护、访问控制、确认、空状态和多字段表单。
- `examples/full_demo`

`examples/web_ui_gallery/README.md` 记录了本地构建、烧录查看和 selftest env 的使用方式。

验证重点：

- PC 宽屏不拉散。
- 手机端不重叠。
- 表单控件对齐。
- 分页信息完整。
- 分页可选择每页条数、能直接跳页，并显示当前页附近页码。
- 多字段表单按短字段、中等字段和长字段组织宽度，不平均拉满整行。
- 动作链接和分页跳转有足够点击高度，状态标签只表达状态。
- 成功和失败状态可见。
- 刷新不重复提交。
- 皮肤变量覆盖后仍保持语义清楚。

## 12. 样式调整回路

实现和试用过程中允许调整样式。

调整原则：

- 优先改基础 CSS 变量或通用 class。
- 其次改 helper 输出结构。
- 不在业务页面堆一次性 CSS。
- 不为了单个项目加入业务组件。
- 每次样式调整先更新 `examples/web_ui_gallery`，必要时同步 `examples/full_demo`，再扩散到业务项目。

影响判断：

- 颜色、间距、字号、圆角属于小改。
- 配置行、分页 footer、导航结构属于中改。
- 页面能力分类或 helper API 变化属于大改。

大改必须先回到设计文档和示例页验证。
