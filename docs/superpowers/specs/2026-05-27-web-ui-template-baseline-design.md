# Web UI 模板基线设计稿

状态：首版页面能力已实现并在内置页、`examples/web_ui_gallery` 和文档中收束；后续只按真实接入反馈迭代。

## 1. 目标

为 Esp32Base 和业务项目沉淀一套轻量、紧凑、统一的 Web UI 模板基线，解决业务页面反复调样式、表单页面空间浪费、PC 和手机体验不一致、重复提交风险高的问题。

这套模板服务两类页面：

- 基础库内置页面，例如 System、Logs、App Config、OTA、WiFi/Auth。
- 业务自定义页面，例如设备状态、业务配置、记录列表、一次性操作。

模板按页面能力分类，不按业务功能分类。灌溉、接水、风扇、FarmAuto 只作为验证场景，不作为分类依据。

## 2. 边界

符合现有 `docs/04_web.md` 的 Web 定位：

- Web 是小型局域网管理界面。
- 不做 SPA。
- 不引入大型前端框架。
- 不依赖 WebSocket。
- 不做大型 Web 管理平台。
- 应保持资源占用可控，并允许业务 CSS 覆盖。

首版只沉淀：

- CSS 基线。
- HTML 结构约定。
- 少量轻量 helper。
- 示例页面。

首版不做：

- 完整主题系统。
- 动画和图表框架。
- 复杂前端路由。
- 大型组件库。
- 统一业务数据模型。
- 运行时主题编辑器。
- 大量图片或装饰性视觉资产。

## 3. 基础壳层

基础壳层是所有页面共享的外壳。

推荐结构：

1. 设备身份栏：在线状态点、设备名、短元信息。
2. 导航栏：横向紧凑导航，手机端允许横向滚动。
3. 页面标题区：当前页面标题，可选一句短说明。
4. 页面内容区：状态、列表、配置、操作或反馈。

关键规则：

- 去掉装饰性品牌方块，使用在线状态点表达有效信息。
- PC 最大内容宽度约 1180px，避免宽屏拉散。
- 正文 14px，页面标题约 18px，section 标题约 16px。
- 控件高度 32-34px。
- section 间距约 12px，内部 padding 10-12px。
- 圆角控制在 6-8px。
- 语义色只用于成功、警告、危险和信息提示。

### 3.1 皮肤策略

首版支持 CSS 变量级皮肤，不做完整主题系统。

规则：

- 默认主题使用中性灰背景、白色内容面、低饱和主色和明确语义色。
- 业务项目可通过覆盖 CSS 变量调整主色、背景、边框和强调色。
- 语义色的含义保持稳定，不能把危险、警告、成功混用为装饰色。
- 可提供少量预设变量，但不提供运行时主题编辑器。
- 不依赖图片皮肤、大量渐变或装饰资产。
- 内容结构优先于视觉装饰，视觉只负责让状态、层级和操作关系更清楚。

## 4. 核心模板

### 4.1 状态概览模板

用途：设备首页或任何需要快速判断当前状态的区域。

结构：

- 状态条。
- 关键指标。
- 下一步或最近记录。
- 主操作入口。
- 异常摘要。

规则：

- 首行只回答“设备现在是否正常”。
- PC 首屏关键指标不超过 4 个。
- 手机端默认 2 列指标。
- 首页只放 1 个主要操作和 1 个次要入口。
- 异常优先级高于普通摘要。
- 不做大卡片仪表盘。

### 4.2 访问控制模板

用途：登录、权限不足、会话失效、只读受限。

结构：

- 简洁登录表单。
- 权限不足说明。
- 会话失效提示。
- 可继续访问的只读入口。
- 返回目标页面。

规则：

- 访问控制进入首版模板范围。
- 登录页使用统一表单和按钮样式，不混入业务配置页。
- 权限不足必须说明原因和可继续做什么。
- 不使用浏览器弹窗代替页面级反馈。
- 提交仍使用 POST -> 303 -> GET。

### 4.3 统计摘要模板

用途：累计值、分组汇总、轻量趋势、占比和最近变化。

结构：

- 汇总数字。
- 分组列表。
- 可选轻量趋势。
- 最近变化说明。
- 跳转到记录页的入口。

规则：

- 统计摘要进入首版模板范围。
- 统计摘要补齐状态概览和记录列表之间的空档。
- 不引入图表框架。
- 简单趋势用表格、数字、CSS 条形或极简内联元素表达。
- 数据量较大时链接到记录页或导出，不在摘要页堆满明细。

### 4.4 列表记录模板

用途：历史记录、事件、对象列表等多条数据展示。

结构：

- 紧凑筛选区。
- 表头。
- 数据行。
- 分页 footer。
- 空状态。
- 可选导出入口。

分页规则：

- PC 端使用左统计、中导航、右跳页。
- 显示总条数、每页条数、当前页和总页数。
- 提供首页、上一页、下一页、尾页。
- 总页数可知时显示跳页。
- 如果后端只支持游标分页，则不显示跳页。
- 修改筛选条件后回到第一页。
- 手机端隐藏复杂页码，保留上一页、下一页、首页、尾页和总数摘要。

筛选规则：

- 筛选区不平均拉满宽度，采用紧凑工具栏。
- 时间范围支持最近 24 小时、最近 7 天、最近 30 天和自定义。
- 自定义时间展开开始时间和结束时间。
- 翻页时保留当前筛选条件。

### 4.5 配置编辑模板

用途：业务配置、通道配置、计划配置和低频参数编辑。

结构：

- 配置列表。
- 每项显示当前值、必要说明和修改入口。
- 简单字段行内展开。
- 多字段对象进入独立编辑页。
- 保存结果通过横向状态提示。

规则：

- 配置页默认先展示当前值，不直接铺开大表单。
- 简单字段适合行内编辑，例如短文本、数字、开关、单个枚举。
- 多字段对象使用独立编辑页，例如计划、通道、滤芯、复杂策略。
- 每项必须有一句必要说明，说明影响范围，不写长教程。
- 高风险配置或重置动作进入确认保护页。
- 系统级基础参数优先使用 App Config。
- 业务运行状态不放进配置表单。

### 4.6 操作命令模板

用途：开始、停止、跳过、测试、立即执行等一次性动作。

规则：

- 命令不是配置，不保存为长期参数。
- 命令页必须先判断可执行条件。
- 设备空闲、时间可信、无严重异常、权限通过时才显示主执行按钮。
- 执行中禁止显示新的开始按钮。
- 停止按钮应比开始按钮更容易找到。
- 拒绝执行必须说明原因和下一步处理。
- 高风险命令进入确认保护页。

典型状态：

- 可执行。
- 执行中。
- 拒绝执行。
- 执行完成。
- 执行失败。

### 4.7 确认保护模板

用途：不可逆或高风险操作前的安全门。

适用：

- 恢复出厂。
- 重置计数。
- 清除故障。
- 保存高风险校准。
- 格式化文件系统。
- 重启或维护操作。

规则：

- 高风险动作必须进入独立 GET 确认页，不能只靠浏览器 `confirm()`。
- 确认页展示操作对象、当前状态、影响范围和提交后返回位置。
- 必要时要求输入确认文本。
- 服务端 POST 时必须重新校验状态和权限。
- 一次性 token 只能消费一次。
- 成功、失败或拒绝都应可追溯到业务记录或系统日志。

### 4.8 横向状态模板

用途：所有页面共享的状态变体。

包括：

- 保存成功。
- 保存失败。
- 无数据。
- 未配置。
- 运行中拒绝。
- 权限不足。
- 时间未同步。
- 存储或网络不可用。

规则：

- 保存成功/失败用顶部短提示。
- 页面主体没有内容时才使用大空状态。
- 空状态必须说明为什么为空，以及下一步可以做什么。
- 错误不能只显示“失败”，必须给出可读原因。
- 时间未同步要说明受影响功能和仍可继续使用的功能。
- 手机端空状态最多保留 1 个主按钮和 1 个次按钮。

### 4.9 流程向导模板

用途：校准、首次设置、复杂维护流程。

规则：

- 流程按“依据、实测、核对、保存”组织。
- 不把校准做成普通配置表单。
- 保存前展示旧值、新值、变化幅度和影响范围。
- 运行中或状态不可信时禁止保存关键校准。
- 保存仍使用 POST -> 303 -> GET。

边界：

- 流程向导进入首版模板范围。
- 不是每个业务项目都必须启用，但基础库应提供统一结构和样式。
- 向导只解决多步骤页面组织，不接管具体校准算法或业务规则。

### 4.10 诊断维护模板

用途：系统信息、只读诊断、维护入口、长任务状态和受控原始片段。

结构：

- 关键诊断摘要，例如 WiFi、时间、存储、任务状态和版本信息。
- 维护操作入口，例如导出、扫描、上传、重启、清理或自检。
- 长任务状态，例如等待、执行中、完成、失败和可重试。
- 受控原始片段，例如最近日志、错误上下文或可复制调试信息。

规则：

- 诊断维护进入首版模板范围。
- 默认只读优先，危险维护动作必须进入确认保护页。
- 长任务不单独成为页面类型，作为操作命令或诊断维护里的状态变体。
- 原始数据不单独成为模板，只能作为诊断维护页里的受控片段。
- 原始片段必须限制长度，允许复制或导出，不能做无限滚动调试平台。
- 诊断页不能替代业务首页，也不能挤占普通业务页面主流程。

## 5. 全局提交规则

页面表单和命令提交统一使用：

```text
POST -> 303 Redirect -> GET
```

规则：

- 成功和失败都跳回 GET 页面。
- 刷新不能重复提交。
- 前端禁用按钮只能防连点，不能替代服务端校验。
- 服务端必须重新解析参数、校验范围、检查设备状态和权限。
- GET 页面通过 query 或结果状态显示短提示。

## 6. 常见组合页

模板不是按业务页面分类，但常见业务页可由能力模板组合。

| 组合页 | 组成 |
| --- | --- |
| 设备首页 | 基础壳层 + 状态概览 + 统计摘要 + 操作命令入口 + 横向状态 |
| 设备记录页 | 基础壳层 + 列表记录 + 横向状态 |
| 设备配置页 | 基础壳层 + 配置编辑 + 确认保护 + 横向状态 |
| 设备操作页 | 基础壳层 + 操作命令 + 确认保护 + 横向状态 |
| 校准/首次设置 | 基础壳层 + 流程向导 + 确认保护 + 横向状态 |
| 诊断维护页 | 基础壳层 + 诊断维护 + 操作命令 + 确认保护 + 横向状态 |
| 访问受限页 | 访问控制 + 横向状态 |

## 8. 实现边界决策

以下是首版实现采用的专业判断，不再作为开放式页面方案继续发散：

- CSS 以内置基础样式形式提供，作为 Esp32Base Web 基线的一部分；业务页面可通过 CSS 变量做少量覆盖。
- 不做完整主题系统；首版只保留变量级换色能力，避免增加资源占用和维护复杂度。
- 业务页面 helper 只提供结构能力，不封装具体业务组件。推荐 helper 包括 page、nav、title、section、row、actions、notice、form result 和 pagination。
- 分页应提供基础模型和渲染 helper。业务只传总数、页码、每页数量和查询参数，不在每个业务项目里重复手写分页 UI。
- PRG redirect helper 纳入 Web 层，作为表单和命令提交的默认推荐路径。所有页面提交都应使用 POST -> 303 -> GET，避免刷新重复提交。
- 示例页放在 Esp32Base 示例中，并在文档中保留结构说明。静态原型只能用于设计沟通，不能替代可编译示例。
- 首批不主动重做 App Config。App Config 当前体验可接受，首批优先解决业务自定义页面样式、表单、分页和提交问题；后续再评估内置页统一。
- 访问控制进入首版模板范围。
- 统计摘要进入首版模板范围。
- 流程向导进入首版模板范围，但不是每个业务项目必须启用。
- 诊断维护进入首版模板范围，但只提供受控结构，不做复杂调试平台。
- 长任务不单独成为页面类型，作为操作命令或诊断维护里的状态变体。
- 原始数据不单独成为模板，只能作为诊断维护中的受控片段。
