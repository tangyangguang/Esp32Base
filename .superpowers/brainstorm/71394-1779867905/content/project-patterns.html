Real ESP32 project patterns

The UI system should be driven by recurring device workflows across Faucet, Fan, Irrigation, FarmDoor, and FarmFeeder.

Faucet

Overview, presets, filters, records, stats, calibration from latest real water record, and App Config for low-frequency safety/metering parameters.

Fan

Live control, timer, runtime reset, real-time trend chart, history config, settings, and IR learning workflow.

Irrigation

Overview, manual watering, recent plans, plan editor, records/events, settings, debug status, and CSV export.

FarmAuto

Door and feeder dashboards, records, diagnostics, calibration, schedule, base-info, refill, confirmation pages, and App Config boundary rules.

Repeated page types
1

Status Dashboard

Device snapshot, current operation, alerts, key metrics, recent events.

2

Operation Page

Manual start/stop, one-shot action, progress polling, disabled/busy states.

3

Configuration Surface

Low-frequency App Config, business settings, single-item edit, grouped fields.

4

Records and Diagnostics

Paginated tables, filters, recent events, export, hardware/storage health.

5

Calibration and Maintenance

Guided workflows, two-step confirmation, irreversible actions, traceable results.

Recommended product position

Embedded Device Console Kit

Not a generic web theme. Not a marketing page. Not a full SPA. It should be a compact, reusable console system for ESP32 products: structured pages, shared CSS components, page templates, App Config polish, and static prototypes that match what can actually run on the MCU.
