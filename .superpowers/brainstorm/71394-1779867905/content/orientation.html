Esp32Base Web UI: professional framing

We are not just choosing colors. We are defining a small embedded design system with strict resource and maintenance boundaries.

Decision frame

1. Operating Surface

Status, WiFi, OTA, logs, system tools, and business configuration pages need one visual language.

2. Resource Budget

CSS, JS, images, flash size, heap, chunked response behavior, and slow WiFi must shape the design.

3. Component Library

Forms, tables, key-value panels, alerts, tabs, confirmations, progress, and compact controls must be reusable.

4. Adoption Model

Business projects should choose a proven pattern and fill content, without debugging layout from scratch.

What we will design before implementation
A

Style Direction

Neutral palette, density, typography, spacing, state colors.

B

Page Patterns

Status dashboard, config form, maintenance tools, logs, OTA, captive portal.

C

Technical Packaging

Built-in CSS, optional prototype assets, scoped theme CSS, example pages, and docs.

D

Acceptance Standard

Byte budget, mobile readability, form density, no layout drift, real ESP32 response checks.
