二、表单页面应该怎么做

表单页痛苦的根源通常是：字段太多、单位混乱、保存范围不清、移动端宽度不稳、用户不知道改动影响。解决方式不是把表单做大，而是按风险和频率拆成不同表单模式。

A. 单项编辑列表（推荐用于低频参数）

先展示当前值，点击“修改”只改一个参数或一小组参数。

三、我的专业建议

不要让用户每个项目重新选样式

我们应该在 Esp32Base 里定义“页面模板目录”。业务项目只选择页面类型：总览、操作、记录、诊断、校准、配置、确认。每类页面有默认布局，不需要每次重新发明。

也不要一次只选一种页面

页面逻辑应该成套提供。你不需要今天只选首页、明天再选表单。我们先确认整套模板，再逐页微调最痛的页面，尤其是表单页和记录页。

默认组合首页/手动页用状态条 + 操作表；诊断页用键值矩阵；记录页用过滤条 + 数据表；配置页用单项编辑列表；校准页用引导流程；危险动作进入确认页。
表单页重点App Config 默认应从“长表单”升级为“分组紧凑 + 修改前可读 + 保存前核对”。业务设置页优先“一次只编辑一个对象”，比如单个滤芯、单个计划、单个通道。
资源边界基础库默认 CSS 只放核心组件；复杂业务组件按页注入。皮肤只用少量 CSS 变量，不做复杂主题系统。
