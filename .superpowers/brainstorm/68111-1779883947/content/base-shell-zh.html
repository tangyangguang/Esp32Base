基础壳层

先统一底座，再设计状态、列表、配置、操作等模板。这里不绑定任何具体业务。

轻量 CSS PC / 手机一致

一、专业判断

不使用重型前端框架ESP32 页面要小、稳定、可内嵌。基础库只提供 CSS 类和少量行为约定。
不做营销式页面不要大 hero、大插图、大留白。设备页面应优先可读、可扫、可操作。
不滥用卡片卡片只用于重复项、工具块、确认块。页面区块用紧凑 section，不做卡套卡。

四、基础规则

后续模板继承
项目建议基线原因
页面宽度PC 最大 1180px，手机左右留 10px。宽屏不拉散，手机不贴边。
字体正文 14px，页面标题 22-24px，section 标题 16-17px。设备控制台不需要大字排版，重点是密度和清晰。
圆角统一 6-8px，不使用大圆角。保持工具感，避免显得像营销卡片。
控件高度按钮/输入框 32-34px，手机可自然撑大。PC 紧凑，手机仍可点。
区块间距section 间距 12px，内部 padding 10-12px。减少大片空白，保持视觉分组。
颜色默认灰白底 + 深色文字 + 单一主色，危险/警告/成功只作语义色。简洁朴素，避免主题复杂度。
导航PC 横向紧凑导航，手机横向滚动或换行，不做复杂侧栏。节省空间和实现成本。
提示成功、警告、错误使用统一 notice 样式。后续所有 PRG 结果反馈复用。

五、基础控件

按钮普通、主按钮、危险按钮、禁用态。文字短，避免一排太多按钮。
表单控件input、select、checkbox、textarea 使用同一高度和边框。
标签状态ok/warn/danger/blue/muted，所有页面统一颜色语义。
提示块notice 用于 PRG 保存结果、错误原因、空状态说明。

六、不建议采用的方向

不做多主题系统先只保留少量 CSS 变量。皮肤可后续扩展，但不能成为首批复杂度。
不做复杂栅格框架不引入 Bootstrap/Tailwind。需要的只是固定几种 grid 和 section。
不把说明写成长文页面说明要短，具体帮助信息放在字段说明或文档中。

七、我的建议

基础壳层就按这套定：紧凑顶部导航、简短标题区、1180px 主容器、8px 以内圆角、32-34px 控件、12px 区块间距、统一语义色。后续所有模板都继承它，不再每个页面重新调视觉规则。
